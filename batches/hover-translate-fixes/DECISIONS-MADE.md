# hover-translate-fixes

- [Hover translate fixes] T1 — shared the translations block as plain TS+CSS under `extension/src/common/ui/translationsBlock/`, consumed by the popup via its existing `@shared` vite alias — because that alias already exists and both build units can import plain TS/CSS without a bridge package.
- [Hover translate fixes] T2 — pill visibility and "has recorded" persist in `sessionStorage` (per tab, per origin) rather than a cross-tab store — because the requirement is "per tab, survives navigation," which is exactly what tab-scoped sessionStorage gives for free.
- [Hover translate fixes] T3 — kept the existing 1s `getTabRecordingStatus` poll for cross-tab state rather than adding a push channel — because the design doc said the poll is assumed sufficient and a push channel is strictly more moving parts for the same observable latency.
- [Hover translate fixes] T4 — waveform peaks are computed by decoding the full clip once (`AudioContext.decodeAudioData`) and bucketing max amplitude into 160 columns drawn on a `<canvas>` — because it needed no new dependency and runs once per recording, not per frame.
- [Hover translate fixes] T5 — the inline capture surface isolates via a closed-mode-adjacent (actually `open`) Shadow DOM with its CSS injected as `<style>` text (via `?raw` imports), not heavily-specified host-page CSS — because Shadow DOM is the only mechanism that's actually immune to arbitrary host-page selectors.
- [Hover translate fixes] T6 — kept a `"none"` type chip in the audio-send form; choosing it omits the `type` key entirely rather than sending a literal `"none"`, so stabbur's existing default-to-`word` behavior is unchanged.
- [Hover translate fixes] T7 — the note surfaces (Quick Note, inline capture) follow `prefers-color-scheme` rather than detecting "is this host page a video player" — because the inline popup is positioned beside the selection, not over the video canvas, so the page's general theme is already the relevant signal; true per-surface video detection was judged not worth the added complexity for this package.
- [Sizing, click-to-capture, audio page] T1 — the scale is three custom properties (`--tt-fs` applied verbatim, unitless `--tt-scale` for every other size and metric, `--tt-max` for the clamp) plus a shared `surfaceSizing.ts` owning ranges/clamping — because applying the configured px verbatim is what makes a 14px setting measure exactly 14px, which `calc(13px * 1.0769)` would miss by 0.0003px.
- [Sizing, click-to-capture, audio page] T4 — a stored `{size: small|medium|large}` migrates onto 11/13/16px rather than being discarded — because those px values are exactly what the three steps rendered at, so an operator who chose Large keeps a large tooltip; the pre-package-1 eight-field theme still resolves to defaults, carrying nothing the four controls can use.
- [Sizing, click-to-capture, audio page] T2 — the `smia unreachable` tag moved to a `.tt-foot` amber status strip below the last band, built only when the fallback collapse fires — because it was the mocked and operator-reviewed answer.
- [Sizing, click-to-capture, audio page] took the base/mockup 11.5px for the block's gloss/note/error/warn text over the old `.tt-size-md` 11px — because the deleted size class and the base rules disagreed (11 vs 11.5) and one derivation cannot reproduce both; the tooltip's "no match"/error text is 0.5px larger than before, and nothing S3 measures is affected.
- [Sizing, click-to-capture, audio page] the multi-word phrase clamp became `round(width * 1.3)` — because it preserves today's 520/400 ratio while staying proportional as the width slider moves.
- [Sizing, click-to-capture, audio page] wired the click path by injecting `CaptureService` into `TooltipService` as a graph-level reference behind a structural `ICaptureSurfaceOpener` interface, rather than a background message — because the surface then opens synchronously on the click's own task and the two modules stay free of an import cycle, which a message round-trip would have given up for no gain.
- [Sizing, click-to-capture, audio page] also deleted `saveOriginalTextToClipboard`/`saveTranslationToClipboard` and their two locale strings, beyond the setting itself — because K5 requires no trace of copy-original/copy-translation anywhere in the UI.
- [Sizing, click-to-capture, audio page] the shared note-type list exports the five real types plus a separate `NOTE_TYPE_OPTIONS_WITH_NONE` for the audio form — because `none` is a sentinel that omits the `type` key, not a sixth stabbur note type, and flattening all three surfaces to one set would have broken that.
- [Sizing, click-to-capture, audio page] T3 — rebuilt BOTH structural lists (Sent history, Re-home audio) on the `ns-*` tokens rather than leaving them MUI — because leaving them would preserve exactly the two-stitched-together-designs look the finding is about, and the mockup's Sent row is a direct replacement for the MUI list.
- [Sizing, click-to-capture, audio page] local-recording rows are now collapsed by default, one expanding at a time, per the mockup's state 8 — so the slice selector and note form appear on expand; a successful send/assign/discard collapses the row and refreshes both lists, where the old page refreshed only the local one.
- [Sizing, click-to-capture, audio page] the trim warning stays inside the slice selector with the discarded seconds restated beside the send button — because the note form now sits between the two and the mockup's single adjacent placement is no longer reachable.
