# DECISIONS-MADE — stabbur-redesign

Tier-2 autonomous decisions, one line each (docs/15).

- [Stabbur editor redesign] chose a new optional `absorbed_values: {<absorbed id>: {fields}}` on `POST /api/notes/merge` over making the UI PATCH the open note before a "this note into other" merge — because save-then-merge must stay one transaction and the takes must read the open form's unsaved values, exactly as `survivor_values` guarantees for the other direction; an absorbed note must be draft both stored and as submitted.
- [Stabbur editor redesign] chose merge de-duplication of translations by (lang case-insensitive, trimmed text) and of examples by trimmed text over exact-string comparison — because it matches the old context merge's trimmed-duplicate rule and a stray space or `EN` vs `en` is the same translation.
- [Stabbur editor redesign] chose to re-key saved triage queues' `context_text_presence` filter to `examples_presence` inside the D5 migration over leaving stored queues to fail validation — because a queue must keep meaning what it meant and the column it named no longer exists.
- [Stabbur editor redesign] chose `updated_at` untouched by the D5 migration over bumping it — because the builder regenerates minted content on every publish anyway (D6) and a bump would make every migrated note look operator-edited.
- [Stabbur editor redesign] chose notes-list params `type`/`pos`/`origin`/`missing` as comma-separated (or repeated) lists, `audio=has|none`, `missing=ipa,translations,examples,lemma` (ANDed), `updated_within=today|week|month` as rolling 24h/7d/30d, and sorts `complete_asc`/`complete_desc` over new parameter names per value — because single values keep working unchanged for existing callers and the rolling windows reuse `updated_since`'s semantics with no timezone guess.
- [Stabbur editor redesign] chose to return `completeness: {filled, applicable}` on each authoring-list row, computed by the same SQL expression the sort uses, over letting the UI recompute it — because the Complete column and the least-complete sort then cannot disagree; paradigm slots are ui.js's INFLECTION_SHAPES for substantiv/adjektiv/verb (adverb's single `form` is not a paradigm) and the grammar rule counts only on type=grammar.
- [Stabbur editor redesign] chose to put a non-stored `duplicated_from: <original id>` on the duplicate endpoint's response over a stored "copy of" column — because the label is needed only when the copy opens and D11 forbids copying provenance into the row.
- [Stabbur editor redesign] chose to reject `value_color: "custom"` when neither the request nor the stored row has a `value_color_custom` (and to reject clearing it while custom is selected) over storing a custom choice with no colour — because "custom" means "use that colour" and a missing one would silently fall back.
- [Stabbur editor redesign] chose to rename the import tool's local SQLite field to `examples` (list, `normalized.examples_json`, added to old stores by `store._migrate`) over translating `context_text` at push time — because the operator asked for no compatibility shims and every import stage before push is a full re-run.
- [Stabbur editor redesign] chose to spell the retired field indirectly (`["context", "text"].join("_")`) in the builder's two no-fallback/byte-identity unit tests over naming it literally — because C02/C03 need a payload carrying it and the old formula as reference while C04 requires `grep -rn context_text mjolnir/builder` to print nothing.
- [Stabbur editor redesign] chose to correct builder's projector.test.js "transcription leads" expectation to `[&ensp;hʉːs ]` over leaving it red — because the operator's own b41aa964 deliberately dropped that space in transcriptionHtml and the test had not followed; no production code changed.
- [Stabbur editor redesign] chose a 960 px phone/desktop breakpoint over the mockup's 760 px switch — because at 960 px the 1240 px-capped wrap still gives each of the three desktop columns ≥ 280 px (design D3), which 760 px cannot.
- [Stabbur editor redesign] chose to substitute the stored theme/value colour into index.html server-side (app.py, `null` on any DB failure) with a localStorage copy as fallback, over a localStorage-only cache — because a fresh browser profile (C14) would otherwise flash the defaults before the settings request returns.
- [Stabbur editor redesign] chose Google Fonts (the mockup's exact stylesheet link) over self-hosting — because the faces then match the reference byte for byte and IPA renders in Charis SIL; offline the font stacks fall back cleanly.
- [Stabbur editor redesign] chose a small strip-list sanitiser (drop script/style/iframe/object/embed/form/…, every on* attribute and javascript:/vbscript:/data:text URLs) over adding a sanitiser library — because there is no build step (D46) and the HTML is single-operator content behind auth.
- [Stabbur editor redesign] chose to show the noun's stored `article` as its own inflection cell ("artikkel", first) over hiding it behind the mockup's four labels — because the data model stores the article separately and server completeness requires it.
- [Stabbur editor redesign] chose to keep the adverb's single `form` field editable but not counted in the Word marker over dropping it — because existing notes carry it, while the done-markers must agree with the server's completeness (substantiv/adjektiv/verb only).
- [Stabbur editor redesign] chose to make audio part of the form in every context (saved with Save / the verdict, marks the note dirty) over the note page's old immediate PATCH — because one editor means one save model, and the mockup marks audio changes dirty.
- [Stabbur editor redesign] chose to query every enabled provider per kind (cached and shared between identical lookups) and let prefill pick the first provider in Settings order, over the old stop-at-first walk — because the badges need counts and the boxes need answers; the pick, and so the prefill result, is unchanged.
- [Stabbur editor redesign] chose to fetch suggestions only on Prefill or when a sheet opens when prefill timing is "on demand", over always prefetching for badges — because the operator chose on-demand precisely to avoid lookups on open.
- [Stabbur editor redesign] chose to save unsaved edits before Duplicate (triage and note) over duplicating the stored row — because the copy should be what the operator sees, as save-then-merge already guarantees for merges.
- [Stabbur editor redesign] chose to put "Edit queue…" / "Save as new queue…" in the queue menu, opening a chip-based queue sheet, over keeping the old inline select-based queue editor — because native selects are gone (C16) and the sheet is the mockup's filter-sheet language.
- [Stabbur editor redesign] chose to keep the "reuse a recording from another note" search (stabbur-triage-queues D9) as a quiet section in the audio sheet over dropping it — because D14 does not list it among the removals.
- [Stabbur editor redesign] chose to open a similar note in a new tab from triage (and in place from the Notes context) over always navigating — because the belt's position and unsaved edits live in memory.
- [Stabbur editor redesign] chose an in-place "Replace?" second click for text-from-audio when the headword already holds different text, over the old confirm() dialog or a silent replace — because stt-text-suggest D5 asks to confirm and the redesign forbids browser dialogs.
- [Stabbur editor redesign] chose a fixed 50-row page with ‹ › over the old 20/50/100 page-size select — because the mockup's pager has no size control and selects are gone.
- [Stabbur editor redesign] chose to disable "Into this note" with the reason when the similar note is ready (alongside the specified ready-open-note case) over letting the server refuse it — because only a draft can be absorbed in either direction.
- [Stabbur editor redesign] chose to give part of speech its own stored provider list (`providers.pos`), reconciled against smia's INFLECTIONS catalogue, over a separate catalogue entry — because smia has no part-of-speech endpoint (the sheet reads the inflections lookup's `pos`), yet the mockup orders it independently; text from audio uses smia's own `stt` catalogue.
- [Stabbur editor fixes] chose to derive the lemma AFTER `E.base` is taken, so it reads as an unsaved edit, over folding it into the baseline — because a lemma inside the baseline leaves Save reading "Saved" and the derived value would never reach the database.
- [Stabbur editor fixes] chose Force prefill as a ⋯ tray item in the triage and note contexts with no confirmation dialog, over a second button in the pinned bar or a confirm step — because New note has nothing to overwrite, the bar is already five controls wide on a phone, and every field it replaces stays individually editable.
- [Stabbur editor fixes] chose to group the translations sheet by language, each group carrying its own provider order, over one flat provider list ordered by the first target language — because with per-language orders a flat list has to contradict Settings for every language but one.
- [Stabbur editor fixes] chose to keep the generic `translations` provider preference in storage as the seed a new language's list resolves from, while removing it from the Settings page, over deleting it on migration — because a language added later should start at the order the operator already configured, not at smia's catalogue order.
- [Stabbur editor fixes] chose to keep a stored `translations:<lang>` order for a language removed from Translation languages, over pruning it — because re-adding the language then restores its order instead of silently resetting it.
- [Stabbur editor fixes] chose "up to M sentences NOT already taken" per examples provider over "that provider's first M regardless of overlap" — because a second provider whose first sentences duplicate the first provider's would otherwise contribute nothing while appearing to have been asked.
- [Stabbur editor fixes] chose to apply the slash split to translation candidates only, never to examples, IPA or text — because a slash inside a sentence or a transcription is content, not a list of alternatives.
- [Stabbur editor fixes] chose to accept a dropped file as audio by MIME type OR a known audio extension, over MIME type alone — because several file managers and archive tools hand over an empty `type`, which would refuse a legitimate mp3.
- [Stabbur editor fixes] chose the new migration's de-duplication rule to be `d5e1a7c39f20`'s (drop only duplicates the split itself produced) over collapsing every `(lang, text)` duplicate in a note — because the earlier migration deliberately left pre-existing duplicate rows alone and this change undoes joins, it is not a de-duplicator.
