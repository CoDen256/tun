# DECISIONS-MADE — stabbur-redesign

Tier-2 autonomous decisions, one line each (docs/15).

- [Stabbur editor redesign] chose a new optional `absorbed_values: {<absorbed id>: {fields}}` on `POST /api/notes/merge` over making the UI PATCH the open note before a "this note into other" merge — because save-then-merge must stay one transaction and the takes must read the open form's unsaved values, exactly as `survivor_values` guarantees for the other direction; an absorbed note must be draft both stored and as submitted.
- [Stabbur editor redesign] chose merge de-duplication of translations by (lang case-insensitive, trimmed text) and of examples by trimmed text over exact-string comparison — because it matches the old context merge's trimmed-duplicate rule and a stray space or `EN` vs `en` is the same translation.
- [Stabbur editor redesign] chose to re-key saved triage queues' `context_text_presence` filter to `examples_presence` inside the D5 migration over leaving stored queues to fail validation — because a queue must keep meaning what it meant and the column it named no longer exists.
- [Stabbur editor redesign] chose `updated_at` untouched by the D5 migration over bumping it — because the builder regenerates minted content on every publish anyway (D6) and a bump would make every migrated note look operator-edited.
- [Stabbur editor redesign] chose notes-list params `type`/`pos`/`origin`/`missing` as comma-separated (or repeated) lists, `audio=has|none`, `missing=ipa,translations,examples,lemma` (ANDed), `updated_within=today|week|month` as rolling 24h/7d/30d, and sorts `complete_asc`/`complete_desc` over new parameter names per value — because single values keep working unchanged for existing callers and the rolling windows reuse `updated_since`'s semantics with no timezone guess.
- [Stabbur editor redesign] chose to return `completeness: {filled, applicable}` on each authoring-list row, computed by the same SQL expression the sort uses, over letting the UI recompute it — because the Complete column and the least-complete sort then cannot disagree; paradigm slots are ui.js's INFLECTION_SHAPES for substantiv/adjektiv/verb (adverb's single `form` is not a paradigm) and the grammar rule counts only on type=grammar.
- [Stabbur editor redesign] chose to put a non-stored `duplicated_from: <original id>` on the duplicate endpoint's response over a stored "copy of" column — because the label is needed only when the copy opens and D11 forbids copying provenance into the row.
- [Stabbur editor redesign] chose to reject `value_color: "custom"` when neither the request nor the stored row has a `value_color_custom` (and to reject clearing it while custom is selected) over storing a custom choice with no colour — because "custom" means "use that colour" and a missing one would silently fall back.
- [Stabbur editor redesign] chose to rename the import tool's local SQLite field to `examples` (list, `normalized.examples_json`, added to old stores by `store._migrate`) over translating `context_text` at push time — because the operator asked for no compatibility shims and every import stage before push is a full re-run.
- [Stabbur editor redesign] chose to spell the retired field indirectly (`["context", "text"].join("_")`) in the builder's two no-fallback/byte-identity unit tests over naming it literally — because C02/C03 need a payload carrying it and the old formula as reference while C04 requires `grep -rn context_text mjolnir/builder` to print nothing.
- [Stabbur editor redesign] chose to correct builder's projector.test.js "transcription leads" expectation to `[&ensp;hʉːs ]` over leaving it red — because the operator's own b41aa964 deliberately dropped that space in transcriptionHtml and the test had not followed; no production code changed.
