# shadow-smia-pronunciation
- [Shadow playback, splitting & chapter reading] chose a one-row `shadow_owner` table for the pinned owner id over a key in `shadow_settings` — because it is not a preference: nothing may write it after the migration and the settings API must never list it.
- [Shadow playback, splitting & chapter reading] chose one migration (e5b9c2d47a10) for owner pin + settings table + chapter `title` + `manual_edit_count` over sibling revisions — because the owner check must precede all DDL and one transactional revision keeps "abort changes nothing" true for all of it.
- [Shadow playback, splitting & chapter reading] chose a new `shadowing_split_configs.manual_edit_count` column (incremented by sentence split/merge and chapter break/merge/title, reset by re-analysis, copied by duplicate) over deriving edits from row diffs — because nothing tracked manual edits before and a diff against a re-analysis would need an ffmpeg pass per card render.
- [Shadow playback, splitting & chapter reading] chose `undo: true` on the inverse chapter operation (decrements the edit count) over a dedicated undo endpoint — because D15 defines Undo as the inverse operation, and break/merge responses carry exactly the data the inverse needs (boundarySentenceId, firstTitle, secondTitle).
- [Shadow playback, splitting & chapter reading] chose GET /api/v1/settings answering every known key with its EFFECTIVE value (stored, else default) over returning only stored rows — because every page then reads one shape and no client re-implements the defaults.
- [Shadow playback, splitting & chapter reading] chose to end the phonexa settings import for good the first time phonexa ANSWERS (marker row `_phonexaImportDone`), retrying with 15 s→10 min backoff while it does not, and never overwriting a key the operator stored meanwhile — over a fixed retry budget — because D2 says "once a value is stored, phonexa is never consulted again" and a down phonexa must not lose the operator's earlier choices.
- [Shadow playback, splitting & chapter reading] chose to answer a sentence merge across a chapter boundary with the 400 text "these sentences are in different chapters — merge the chapters first" over the generic "same parent" error — because A9.7 needs exactly that in-page wording and the server already refused the pair.
- [Shadow playback, splitting & chapter reading] chose a Flask route for /manifest.webmanifest (start_url/scope/id = X-Forwarded-Prefix + '/', explicit application/manifest+json) over a static file — because the prefix differs behind the gateway and standalone, and no gateway MIME change is then needed.
- [Shadow playback, splitting & chapter reading] chose icon artwork = the nav's brand mark drawn twice (white square + faint offset "shadow") on the accent teal, full-bleed, plus a maskable 512 — generated by stdlib-only scripts/make_icons.py — over an external tool — because it needs no dependency and can be regenerated.
- [Shadow playback, splitting & chapter reading] chose manifest theme_color/background_color and the page's theme-color metas = studio.css `--bg` (#f6f6f4 light, #0b0c0e dark meta) over the accent teal — because the standalone title bar then matches the page instead of a teal band above a light page.
- [Shadow playback, splitting & chapter reading] chose to run the dev shadow-backend as `docker compose -p smia --env-file ../.env up -d --no-deps shadow-backend` over a standalone `cd shadow && docker compose up` — because a second compose project would start a second Postgres container on the same named volume `tun_postgres_cluster` the running smia project's Postgres already uses (two postmasters on one data dir = corruption).
- [Shadow playback, splitting & chapter reading] chose a ❚❚ pause pill that appears beside a Prepare row's / Explore cell's ▶ only while that preview plays or is paused (replacing the cell's duration) over a permanently visible disabled pause on every row — because the mockups show no pause on previews at rest and D4 only requires a secondary pause; ▶ itself reads ↺ while playing, as in Study.
- [Shadow playback, splitting & chapter reading] chose to keep Prepare and Explore previews on the FULL stored span (untrimmed) over applying Trim silence to them — because that is what they played before this change (Explore's `/segments/<id>/audio` without trim, Prepare's full span) and Prepare is where boundaries are judged.
- [Shadow playback, splitting & chapter reading] chose to show a failed done-and-next write as a persistent red in-page banner at the top of Study's stage (dismissed only by its ✕) over a toast — because the mockup has no state for it and D6 requires the error to be visible and persistent, never a browser dialog.
- [Shadow playback, splitting & chapter reading] chose to make every primary and tray action (incl. ←/→ which nudge the line) inert while splitting, and to let tick-strip / chapter steps / exit cancel the split first, over letting navigation keep the split open — because A11.4 requires the four primaries inert and a split line belongs to one sentence.
- [Shadow playback, splitting & chapter reading] chose to omit the mockup's "NEW" / "NEW FLOW" tags in the `?` overlay over copying them — because they annotate the change for review, like the mockup's dashed outlines, and are not product text.
- [Shadow playback, splitting & chapter reading] chose to drop the phone ⋯ sheet's former "Explore the book" item over keeping it — because D14 and the mockup list the sheet's items exactly; Explore stays one grabber pull away.
- [Shadow playback, splitting & chapter reading] chose to render the "▶▶ Listen" buttons (desktop top bar, phone header line 2) with the `hidden` attribute until audiobook mode (task 8) wires them, over a visible inert button — because a dead control would mislead the operator if the two packages were tested apart.
