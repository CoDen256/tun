# full-sweep
- assembly-tab-usability: `/assemble-defaults` now returns the real `SYNC_TOKEN`, reversing hub's "booleans only, never the token" rule — operator decision; value is `OPERATOR_AUTH_TOKEN`, which the browser already holds, and the route is operator-plane only.
- [Assembly tab usability] chose a regex/literal-anchor text extractor (`tool/src/extractCardStyle.js`, `tool/src/extractCardSymbols.js`) over a full AST-eval of the bundle — because the class/theme objects mix in bundle-relative references (`l.Fonts.poppinsRegular`, `r.default.getTheme()`) that can't be literal-evaluated without executing the whole module graph, while the class names, theme key names and numeric/color constants anchored on are the app's real, stable design-system identifiers (confirmed against the live bundle), not minifier-assigned letters.
- [Assembly tab usability] chose to always list æ/ø/å in the symbol catalogue, with the stock bundle's real occurrence count even when that count is 0 (å does not occur anywhere in this build's own sample content) — over only listing letters the stock bundle happens to contain — because the Norwegian-letter group is the app's fixed orthography, not a frequency sample, and nothing fabricated is shown: the zero is the true extracted count.
- [Assembly tab usability] chose a fading toast ("no audio on this face" / "clip unavailable") reusing the design-session mockup's `.toast`/`.play-pop` treatment over a modal or persistent badge for the no-audio/missing-clip cases — because it was already visually validated in the mockup and is the least disruptive option that still satisfies "visible, non-blocking."
- [Assembly tab usability] chose to memoize the extractor's output in-process (`hub/src/cardPreviewStyle.js`, keyed on the bundle path, recomputed on first use after each hub boot) over writing a generated cache file to disk — over a build-time code-generation step — because `base/` never changes while hub runs, re-running on every boot already satisfies "re-runnable," and a stale on-disk cache file would be exactly the kind of silent drift this item exists to eliminate.
- [Assembly tab usability] chose to recompute `normalize()`/geometry/theme values client-side from an embedded JSON blob (the extractor's own output) over a per-request server recomputation — because switching the simulated device or theme must rescale live (no round trip), and the extracted values are small enough to ship as-is.
