# full-sweep
- assembly-tab-usability: `/assemble-defaults` now returns the real `SYNC_TOKEN`, reversing hub's "booleans only, never the token" rule — operator decision; value is `OPERATOR_AUTH_TOKEN`, which the browser already holds, and the route is operator-plane only.
- [Assembly tab usability] chose a regex/literal-anchor text extractor (`tool/src/extractCardStyle.js`, `tool/src/extractCardSymbols.js`) over a full AST-eval of the bundle — because the class/theme objects mix in bundle-relative references (`l.Fonts.poppinsRegular`, `r.default.getTheme()`) that can't be literal-evaluated without executing the whole module graph, while the class names, theme key names and numeric/color constants anchored on are the app's real, stable design-system identifiers (confirmed against the live bundle), not minifier-assigned letters.
- [Assembly tab usability] chose to always list æ/ø/å in the symbol catalogue, with the stock bundle's real occurrence count even when that count is 0 (å does not occur anywhere in this build's own sample content) — over only listing letters the stock bundle happens to contain — because the Norwegian-letter group is the app's fixed orthography, not a frequency sample, and nothing fabricated is shown: the zero is the true extracted count.
- [Assembly tab usability] chose a fading toast ("no audio on this face" / "clip unavailable") reusing the design-session mockup's `.toast`/`.play-pop` treatment over a modal or persistent badge for the no-audio/missing-clip cases — because it was already visually validated in the mockup and is the least disruptive option that still satisfies "visible, non-blocking."
- [Assembly tab usability] chose to memoize the extractor's output in-process (`hub/src/cardPreviewStyle.js`, keyed on the bundle path, recomputed on first use after each hub boot) over writing a generated cache file to disk — over a build-time code-generation step — because `base/` never changes while hub runs, re-running on every boot already satisfies "re-runnable," and a stale on-disk cache file would be exactly the kind of silent drift this item exists to eliminate.
- [Assembly tab usability] chose to recompute `normalize()`/geometry/theme values client-side from an embedded JSON blob (the extractor's output) over a per-request server recomputation — because switching the simulated device or theme must rescale live (no round trip), and the extracted values are small enough to ship as-is.
- [Calst/pygmalion audio consolidation] left one calst-sourced row (`trettiende`/Oslo/take 1) `status: failed` instead of retrying further — the server answers `HTTP 200 Content-Length: 0` for this exact URL every time (confirmed with a direct `curl -I`, not a transient network error), so no retry policy can make it `ok`. The word's take 0 still downloaded fine, so `/tts` still answers for it with one candidate instead of two. 8,748 of 8,749 manifest rows are `ok`.
- [Shadow studying mode] chose 8 MiB resumable upload slices with abandoned `.part` files swept after 24 h (opportunistically, whenever a new upload starts) over a smaller slice or a cron/scheduler — because a 1 GB book is then ~128 requests rather than thousands, a dropped connection costs seconds, and shadow runs no scheduler so the one moment the disk is about to be used is the honest place to sweep. *(SUPERSEDED, 2026-11-15, by the database-aware-sweep line below: the sweep is NOT opportunistic — shadow does run one 15-minute daemon thread, and since 2026-11-16 that thread also reconciles stuck working states. Only the 8 MiB slice size and the 24 h TTL for still-resumable uploads survive from this line.)*
- [Shadow studying mode] chose mono Opus at 32 kbps with `-vbr on -application audio` (and a fixed `silencedetect` noise floor of -30 dB, keeping the two silence-LENGTH thresholds as the only analysis parameters) over a higher bitrate or a third tunable — because a 12-hour book lands at ~170 MB, a chapter cut stays a `-c copy` stream copy, and design.md §5 requires analysis to be repeatable from the two thresholds already in the data model.
- [Shadow studying mode] chose to KEEP `shadowing_segments.done` as a frozen legacy column — never read, never written — over dropping it, because keeping it makes the lossless conversion auditable after the fact and makes the migration's `downgrade()` non-destructive, at the cost of one dead column.
- [Shadow studying mode] chose a chapter-chunk cache at `<volume>/books/<media_id>/chunks/ch-<segment_id>-<start>-<end>.opus`, wiped wholesale on re-analysis or a chapter split/merge, over an explicit invalidation table — because the boundaries are IN the cache key, so a moved boundary addresses a different file and a stale chunk cannot be served even if the wipe is forgotten; losing the cache costs one re-cut of a few milliseconds.
- [Shadow studying mode] chose to convert only `kind='sentence'` rows with real duration (`end_ms > start_ms`) in the progress migration over converting every `done` row — because a chapter row carrying a stray `done` would cover every sentence inside it and GAIN done sentences, which acceptance criterion 19 forbids, and a flag on a zero-length span carries no progress to lose (the operator's database contains no such row; the exclusion exists so a malformed row cannot wedge the upgrade of a service that is meant to degrade rather than refuse to boot).
- [Shadow studying mode] chose to REMOVE the two client-segmentation endpoints `POST /api/v1/shadowing/media/find-or-create` and `POST /api/v1/shadowing/media/<id>/segment`, and to stop accepting `done` on `PATCH /segments/<id>`, over keeping them as compatibility shims — because both existed only to persist a segmentation the browser computed, which is exactly the path this change deletes, and accepting `done` would create a second, disagreeing source of truth beside the time ranges.
- [Shadow studying mode] chose to draw EVERY waveform on the page (Study's sentence, Prepare's per-row strips, the split scrubber) from one peak envelope computed when the chapter chunk is downloaded — decoded in a throwaway 8 kHz AudioContext, one peak per 10 ms, the buffer dropped immediately — over decoding per sentence or faking a picture — because it keeps acceptance criterion 38 literally true (zero audio requests after the chunk lands), costs ~1 MB of peaks and a transient ~86 MB decode per 45-minute chapter, and never shows the operator a waveform that is not his audio.
- [Shadow studying mode] chose to render a chapter's sentence grid in Explore (and its rows in Prepare) only while that chapter is expanded, with no windowing inside a chapter, over virtualising the list — because a chapter is ~100 cells and what had to be avoided was laying out 1 500 cells for a book nobody has opened.
- [Shadow studying mode] chose to prefetch the NEXT chapter's chunk only once the reader is within 3 sentences of the end of the current one, over prefetching on entry — because "one audio request per chapter entered" then stays literally observable in the network log, which is what criterion 38 is checked against.
- [Shadow studying mode] chose a client-side time estimate for the "transcoding"/"analysing" progress bars, labelled "(estimated)" and capped at 97% until the server reports the real state change, over an indeterminate spinner or a new server progress channel — because ffmpeg exposes no progress to these jobs, the design requires a determinate state, and a bar that says it is a guess is honest where a spinner is merely uninformative.
- [Shadow studying mode] chose to keep the YouTube extractor (`POST /api/v1/youtube-extract`) by feeding its returned WAV into the same chunked upload a dropped file uses, over deleting it with the rest of the old client-side path — because its removal was never asked for; only the time-range selector and the browser-side segmentation were.
- [Shadow studying mode] chose to replace js/user.js's `prompt()`/`alert()` new-profile flow with an inline field, diverging from the vendored phonexa copy for the first time, over leaving it — because task 8.4 forbids a browser modal anywhere in shadow and one modal would hang the automated tester permanently.
- [Shadow studying mode] chose to make a completed upload transcode AND THEN analyse by itself, marking the active config `running` in the same transaction that makes the audio `ready`, over leaving the first analysis to a manual trip to Prepare — because design.md §8 shows a book in an "analysing…" state straight after upload, and a Library row reading "0 chapters · 0 sentences" until the operator finds the Re-analyse button is not that flow.
- [Shadow studying mode] chose to time the "transcoding"/"analysing" estimate against a server-supplied `audioStateSince`/`analysisSince` (the row's `updated_at`, which while the state is working is exactly when that operation began) and to print NO percentage when there is no such timestamp or the browser clock disagrees, over the earlier per-book client-side start time — because one start time per book made every operation after the first open at "97% (estimated) · ~0 s left", and an honest "analysing…" beats a confident lie. *(Supersedes the earlier line on this page choosing a purely client-side estimate: the estimate stays client-side and capped at 97%, but its clock is now the server's and the indeterminate case is admitted.)*
- [Shadow studying mode] chose a database-aware sweep (a `.part` file with no `receiving` upload row is an orphan by construction and reclaimed at once, with a 60-second grace against the start-upload race) driven by a 15-minute daemon thread as well as by the start of an upload, over the mtime-only, upload-triggered sweep — because an operator who abandons an upload and never uploads again otherwise keeps the bytes forever, which is exactly what was found on disk. *(Supersedes the 24 h/opportunistic half of the earlier upload-slice line; 8 MiB slices and the 24 h TTL for still-resumable uploads are unchanged.)*
- [Shadow studying mode] chose `Fmt.clock` (`10:35`, `1:02:30`) as the ONE duration format and deleted `Fmt.long` ("11 min") rather than keeping both — because the stored duration is exact and the rounded form was the only caller's display.
- [Shadow studying mode] chose to treat a `.part` file as claimed by the upload's STATE — `receiving` or `transcoding`, with `transcoding` immune to the TTL rule and the in-process set of running transcodes unioned in — over the `receiving`-only live set, because the old set made every in-flight transcode's own source an orphan whose mtime (the last slice) was already past every grace period.
- [Shadow studying mode] chose to serialise upload slices per upload with a process-local lock and answer a concurrent second slice `409` with the real offset, over queueing it or trusting the offset check, because two PUTs both reading `on_disk = N` produced an interleaved over-length file that `complete_upload` accepted; the database session is also released across the streamed write, so an in-flight slice no longer costs a connection.
- [Shadow studying mode] chose to make the studying-mode migration's `downgrade()` REFUSE with a message naming both losses (progress ranges are the live truth that `done` no longer tracks; dropping `config_id` collapses every config's boundaries into one set) over any structural reversal, and to make `upgrade()` idempotent and skip any book that already holds progress ranges — because the old pair could drop a month of study and then report "verified identical" by re-deriving from the frozen column. *(Supersedes the "keeps `downgrade()` non-destructive" clause of the `done`-column line above: keeping the column makes the conversion auditable, which is still true, but it never made the downgrade safe.)*
- [Shadow studying mode] chose to renumber a merged segment's adopted children densely from `start_ms` over preserving their original indices, because a merge otherwise leaves one chapter holding sentences numbered 0..n AND 0..m, which breaks split's sibling shift and merge's own adjacency test.
- [Shadow studying mode] chose to back the sentence-end stop with `timeupdate` + `ended` + a re-arming wall-clock timer, all funnelling into one idempotent `finish()`, over the requestAnimationFrame loop alone — because rAF is throttled to zero in a background tab and dead on a locked phone, which let a backgrounded sentence run on through the rest of the chapter against criterion 24.
- [Shadow studying mode] chose to reconcile stuck `transcoding`/`running` rows in the janitor's existing 15-minute pass — restarting an interrupted transcode whose complete source is still on disk, marking everything else `failed` with a reason the Library already renders — over a boot-blocking recovery step, because recovery must never delay the port binding (D157) and a book that polls "analysing…" for ever is the failure this replaces.
- [Shadow studying mode] chose to reject `chapterSilenceMs < sentenceSilenceMs` (and either below 50 ms) in `audio.segment_ranges` AND at the config endpoints as a 400 the page toasts, over clamping silently, because chapter cuts must be a subset of sentence cuts and the inverted pair makes a manifest whose `offsetMs + durationMs` runs past the end of the chunk.
- [Builder UI rehaul & data versioning] chose to apply `flush-record-atomicity` BEFORE `builder-ship-strips` — because both edit `pipeline.js`'s `runPublish`/`flushDeck` and the atomicity change restructures the transaction boundaries those functions sit in, so landing the structural change first means the UI change's restamp call and description-sync move are written against their final shape rather than rebased onto it.
- [Builder UI rehaul & data versioning] chose to verify flush-record-atomicity's acceptance criterion 7 via the cross-table break (one occurrence both staged and queued) instead of the duplicate staged row it literally asks for — because D-FA3's own migration 019 adds a unique `(card_id, letter)` index that makes that duplicate uninsertable, so the criterion contradicts the design it belongs to; criterion 5 already asserts the database rejects it.
- [Stabbur merging & dict.cc translations] corrected acceptance criterion 6 and its spec scenario — `inflections`/`translations` are `NOT NULL` in the schema, so the designed "a note whose inflections is null" is an unreachable state; the criterion now asserts the empty value for those columns and asserts NULL-and-empty-string for the genuinely nullable ones (`transcription`, `lemma`, `audio_blob`, `context_text`), because a criterion must be falsifiable against the real schema, not a believed one
- [Stabbur merging & dict.cc translations] chose to serve the audio-reuse search from the existing paged authoring route (`q` + `audio_blob_presence=has`) over adding an endpoint — because the route already filters on exactly those two things, and the design left the choice open provided results can be identified and played.
- [Stabbur merging & dict.cc translations] chose to return ready/draft/missing-audio counts over the FILTERED set alongside the paged rows — because the pre-paging summary derived them from the whole array, and deriving them from one page would silently turn "69 missing audio" into "however many of these 20 are".
- [Stabbur merging & dict.cc translations] chose to reject an out-of-range limit/offset with a 400 rather than clamp it — because a clamped page size makes the pager's own slice-of-total arithmetic lie about what is on screen.
- [Stabbur merging & dict.cc translations] chose to synthesise the three built-in origin queues instead of seeding them as stored rows — because a stored copy could be edited or drift from the behaviour they exist to preserve, and the API can then refuse every write against a `builtin:` id.
- [Stabbur merging & dict.cc translations] chose "…" as the gap marker for a token the IPA assembler could not resolve, and return no value at all when every token is unresolved — because a string of gap markers is not an assembled transcription.
- [Builder UI rehaul & data versioning] chose to leave the now-unused `.flow-rail`/`.flow-stages` CSS in the shared stylesheet rather than delete it alongside the pipeline rail it styled — because the stylesheet is shared by hub and builder (libs/jsservice/layout.js, D46/D80 reversal) and proving no other page uses those classes costs more than the handful of dead rules does.
- [Builder UI rehaul & data versioning] chose to attach a failed ROLLBACK as `err.rollbackError` and destroy that client, rather than let the ROLLBACK's own throw propagate — because the propagating version overwrote the real failure, so `build_jobs.error` and the run log both named the cleanup instead of the cause, which is the opposite of the debuggability this package was asked to add.
