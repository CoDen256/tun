# Tier-2 decisions — shadow-polish

One line per decision (see `docs/15-agentic-workflow.md`).

- [Shadow studying refinements] chose a coarse container seek to 500 ms before the target plus a fine output seek and `-t` over a plain output-only seek — because output-only seeking decodes from byte zero, which is minutes into a 12-hour book, while this pays one pad's worth of decode and still starts at the millisecond; `-t` over `-to` because `-to` is read against a timeline the coarse seek has already moved.
- [Shadow studying refinements] chose a cut-version tag in the chunk filename plus a janitor sweep over a migration or a one-shot boot purge — because the cache is pure derivation, the tag makes an old chunk unaddressable the instant the code changes (correctness without remembering to invalidate), and the sweep only reclaims disk.
- [Shadow studying refinements] chose to pre-cut EVERY chapter of a config, sequentially in one background thread, as soon as its analysis finishes — over a look-ahead window around the cursor — because the boundaries are all known at that moment, one worker leaves the box responsive for the request actually being waited on, and the on-demand path already covers a chapter reached before the pre-cut; a chunk request that finds no cache also warms the rest, which is how books analysed before this change acquire chunks.
- [Shadow studying refinements] chose to derive the speech window from the SAME silencedetect pass that places the boundaries over a second, more sensitive pass — because it adds no decode to analysis and, more importantly, it can only ever trim audio the segmenter already judged silent, so it cannot clip something the detector counted as speech.
- [Shadow studying refinements] chose to STORE the window per segment (`speech_start_ms`/`speech_end_ms`, nullable) over deriving it per request — because split and merge produce boundaries no analysis silence list describes, and a nullable column lets "not computed" and "detection failed" both degrade to the full span, which is always a correct answer.
- [Shadow studying refinements] chose an 80 ms onset guard, a 120 ms tail guard, a 120 ms minimum edge silence and a 300 ms minimum believed window — because 80 ms still leaves under 150 ms of lead-in on a 300 ms silence (acceptance criterion 10) while being conservative enough that a soft consonant onset survives, and a window shorter than 300 ms means the detector is wrong, not that the sentence is.
- [Shadow studying refinements] chose `?trim=1` as an opt-in on the sentence-audio endpoint, with the full stored span as the default — because a caller that knows nothing about trimming must keep getting exactly the sentence it named.
- [Shadow studying refinements] chose to persist the trim setting through the EXISTING `/api/v1/settings/<key>` proxy rather than adding shadow-side storage — because that key-value store already holds the per-profile preferences shadow's settings page reads, and adding a second place for one boolean would breach D151.
- [Shadow studying refinements] chose to trim the learner's take as a WINDOW over the decoded in-memory buffer, played back through an AudioBufferSourceNode with an offset, over re-encoding a trimmed blob — because no trimmed bytes then exist to be persisted by accident, and toggling the setting re-reads the same buffer instead of re-recording.
- [Shadow studying refinements] chose a take-trim detector of 20 ms RMS frames at 6% of the clip's own peak with an 80 ms guard and a 150 ms minimum believed window — because it mirrors the server's conservative-at-onsets rule on bytes the server never sees, and a shorter result means the detector is wrong, not the take.
- [Shadow studying refinements] chose a per-lane `.has-contour` class to gate the waveform's push-back over gating it on contours merely being enabled — because a lane with no contour over it must stay perfectly crisp, and only the lane that actually got a path should recede.
- [Shadow studying refinements] chose dedicated `--ref-contour`/`--usr-contour` hues (indigo over the teal sentence lane, rose over the amber take lane) over reusing each lane's waveform hue — because the operator reported a contour drawn in its own lane's colour reading as part of the waveform rather than on top of it.
- [Shadow studying refinements] chose to track the phone nav's pull gesture on the WINDOW rather than on the 30 px tab, and to auto-hide on the next action rather than on a timer — because a 16 px pull leaves the tab immediately (instrumenting it showed only the pointerdown ever arriving), and "the next action" is an observable event where a stopwatch is not.
- [Shadow studying refinements] chose to keep the four phone primaries as the SAME four `.ctl` buttons restyled at the breakpoint, with a fixed 72x84 box each, over a separate phone-only control cluster — because one set of buttons keeps one set of handlers, and a fixed box is what makes "all four equal, play no larger" measurable rather than approximate.
