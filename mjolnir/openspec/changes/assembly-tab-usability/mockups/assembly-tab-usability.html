This is a static mockup for design sign-off, not a working UI. Nothing submits, assembles or reads from hub. The workbench panes are rendered in the bundle-tool's own light palette whatever theme you are viewing this page in — that is deliberate, the workbench is a light app and these panes are meant to read as an embedded screenshot of it. The interactive parts (explorer search, placeholder rows, token reveal, pickers, device width, card theme, tap-to-play, the throwaway HTML editor) all really respond, so the interaction can be judged rather than imagined.

              What changed on the Assemble tab

              1. 1
                No value is shown twice. The dedicated Label text field and the Patch rev (logic version) number field are deleted. Today LABEL exists both as a top field and as a placeholder row, and the two can disagree; after this the Placeholders list is the single home for every baked value, and what the operator reads is exactly what gets substituted.
              2. 2
                Placeholders arrive resolved, not blank. Instead of empty boxes beside grey hint text that merely mentions the default, every row carries the real value the server would use: the next patch rev, the generated label, the current data version, the public base URLs, and the operator token itself (masked, with a reveal). BUILD_ID stays blank on purpose — hub assigns it at submit time. PATCH_REV and LABEL sit first and are tinted, so it reads that they were promoted into this list rather than quietly lost.

              The earlier draft put a search/filter box above the three pickers. That has been removed — the tab has seven patches, seven pairs and five companions, and filtering was solving a problem that belongs to the Explorer tab. The pickers are plain unfiltered lists again; add → / remove / ▲ / ▼ work as before.

              One box. A numeric query is treated as a module id first and as source text second; anything else is a plain source search, exactly as today.

              What changed on the Explorer tab

              1. 3
                Typing a module number finds the module. Today runExplorerSearch (src/ui-assets/app.js:280) sends the query straight to the server-side full-text source search (/api/sessions/<id>/search?q=) and renders whatever comes back as mod-id + mod-snippet. So typing 2110 returns every module whose source happens to mention 2110 — i.e. every require() call site — and never module 2110 itself. A grep over source text structurally cannot find a module by its own number, because a module's id does not appear in its own body.
                The fix keeps one box and no mode toggle: when the query is numeric, the results gain a pinned top group — a prominent Go to module N jump row tagged exact id, then an ids containing N group (21100, 12110…) if any — and only then the existing source mentions N group with its snippets, under a heading that says plainly that these are source hits. A non-numeric query shows only that one source group, exactly as today: no empty id groups to scroll past.
                Try 2110 (all three groups), 2 (id groups plus source hits), subscription (source hits only), zzz (muted empty state).

              4 One card, three thirds — not three boxes. Geometry, theme values and the class map are taken from the bundle's own study-card component and style maps, not hand-transcribed into hub's CSS: card width normalize(342), borderRadius normalize(20), borderWidth normalize(1), thirds at .28C / .28C / .44C separated by a textDivider hairline, N a plain non-scrolling touchable and E/X wrapped in ScrollViews with paddingVertical normalize(16).               Throwaway scratch editor. Edits are not saved anywhere, are never sent to the builder, and vanish on reload. Nothing typed here reaches a bundle, a patch or hub.
              inserting into N — click a textarea to retarget

              What this is for: find out what is wrong with a minted card here — a class that does nothing, a missing arialFontNormal around an IPA run, a third that overflows — then go fix it in the builder. The editor itself never writes anything.

              Tap, don't scrub. There is no player panel, because the app has none: all three thirds are tappable (onPress Z('N'|'E'|'X')) and only the face named by the card's A field actually carries audio. Hover any third to see it is tappable; tap Back (E) for the play affordance; tap N or X for the "no audio on this face" toast. The speaker glyph lives on the outside gutter label only — nothing is overlaid on the card, because nothing is overlaid on the device.

              Fonts. Faces use 'Poppins', ui-sans-serif, system-ui, and arialFont/arialFontNormal switch to Arial. That switch is deliberate in the app: Poppins has no IPA glyphs, so IPA runs are rendered in the bundled arial.ttf. Hub will serve both arial.ttf and the Poppins family locally rather than falling back — in this mockup you are seeing your system's substitutes.

              What changed on the card preview

              1. 4
                It is now the device's card, not three boxes. One frame, three thirds, real dividers, real per-third scrolling (E and X scroll, N clips — the X face is deliberately long enough to prove it), gutter labels outside the frame so the device rendering stays clean. Tap-to-play replaces the audio element. The class map gained the three selectors hub is missing (supWrap, arialFont, arialFontNormal), with supWrap implemented as the real top-aligned flex row rather than faked with <sup>. A symbol catalogue sits beside the class map, and a throwaway HTML editor lets the operator poke at a minted card's markup to find what is wrong with it before going to fix it in the builder.
