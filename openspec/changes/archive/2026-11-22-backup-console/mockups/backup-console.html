Restore

run from a clone of tun-backup at the repo root

0Get the backup

Any commit is a complete, self-consistent snapshot — pick one, don't merge two.
git clone git@github.com:denyschernyshov/tun-backup.git
cd tun-backup
git log --oneline -5          # pick the commit to restore
git checkout a71f0c4

1A database — mjolnir / stabbur / phonexa / shadow

Restore into an EMPTY database and do not run alembic upgrade head first — each dump carries its own CREATE TABLEs and the alembic_version row.
docker compose exec postgres \
    psql -U tunadmin -d postgres -c 'DROP DATABASE phonexa' -c 'CREATE DATABASE phonexa OWNER phonexa'

# load as the SERVICE role, not the superuser (P42)
docker compose exec -T postgres \
    psql -v ON_ERROR_STOP=1 -U phonexa phonexa < phonexa.sql
⚠ ON_ERROR_STOP=1 is not optional — without it psql reports success having skipped every failed statement.

2Account progress — new step, easy to miss

mjolnir.sql no longer carries userdata table data. Restoring mjolnir.sql alone gives you a mjolnir database with zero account progress. Import each account from its committed export.
# one account
UID=q1Px3MgvOZVBdkpM9DKmFBnDnMi1
docker compose exec -T postgres psql -v ON_ERROR_STOP=1 -U mjolnir mjolnir \
  -c "INSERT INTO userdata (device_id, doc) VALUES ('$UID', \$\$$(cat userdata/$UID.json)\$\$::jsonb)
      ON CONFLICT (device_id) DO UPDATE SET doc = EXCLUDED.doc"

# every account in the snapshot
for f in userdata/*.json; do
  uid=$(basename "$f" .json)
  docker compose exec -T postgres psql -q -v ON_ERROR_STOP=1 -U mjolnir mjolnir \
    -c "INSERT INTO userdata (device_id, doc) VALUES ('$uid', \$\$$(cat "$f")\$\$::jsonb)
        ON CONFLICT (device_id) DO UPDATE SET doc = EXCLUDED.doc"
done
To roll one account back to an earlier day, read the file out of that commit first — git is the version history:
git log --oneline -- userdata/q1Px3MgvOZVBdkpM9DKmFBnDnMi1.json
git show 7a3d550:userdata/q1Px3MgvOZVBdkpM9DKmFBnDnMi1.json > /tmp/rollback.json

3stabbur blobs — blobs/

Flat and content-addressed, so a copy by name is idempotent.
docker compose cp blobs/. stabbur-backend:/blobs/

4phonexa audio — phonexa-audio/

Plain file copy at the same relative paths. The mirror is copy-if-absent, so an edited sample holds its pre-edit audio and a deleted sample is still here (D147).
docker compose cp phonexa-audio/. phonexa-backend:/data/audio/

# to refresh ONE file in the backup on purpose:
docker compose exec backup rm /data/tun-backup/phonexa-audio/lang/nb/ingested/hus.wav
