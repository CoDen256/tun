| D48 | `current.json` is `{schema, buildId, url, sha256, size, label}`; native reads only the middle four and **ignores every unknown field**. Future changes are additive only — there is no schema-2 escape for native | A frozen parser must be tolerant by construction, not by version negotiation it cannot be taught later. `buildId` is filename-validated (`^[A-Za-z0-9._-]{1,64}$`) because it becomes a path component | accepted |
| D49 | **Native never sets `Accept-Encoding`**; `sha256`/`size` always describe the *uncompressed* bundle | Transparent gzip in the HTTP stack is the only arrangement where the hash the server publishes and the bytes native writes to disk stay the same thing. A hand-rolled gzip path in frozen code is an unfixable mistake. Measured 2026-10-20: under gzip Caddy sends the bundle *chunked with no `Content-Length`*, so native must cap bytes while streaming rather than pre-checking a header | accepted |
| D50 | On-device state is **marker files whose names carry the value** (`boot-ok-<id>`, `attempt-<id>-N`, `bad-<id>`), plus two single-token files `active` / `pending` | No read-modify-write, no mutable parsed blob, no corruption mode in frozen code. The directory listing is the truth (04-delivery) | accepted |
| D51 | Validity is checked **twice, differently**: size + sha256 + prefix after download; prefix + non-empty at every activation | Re-hashing 6 MB on the cold-start path is unacceptable (P09), but a truncated file must still never reach React Native. The 26-byte `var __BUNDLE_START_TIME__=` read is the cheap proxy | accepted |
| D52 | Watchdog: the attempt marker is written **before** handing the path over; `boot-ok` makes attempts irrelevant forever; threshold 2; `bad-<id>` is **never auto-cleared**; JS writes `boot-ok` 3 s after root mount | Recovery is publishing a new buildId, which is free; auto-clearing is retry logic inside the one component that can never be debugged. Cost — two fast app kills falsely quarantine a good build — is a fallback, not a brick. **Operator sign-off 2026-10-20: these parameters (threshold 2, 3 s timer, never auto-clear) accepted as-is**, explicitly rather than inherited | accepted |
| D53 | Native requires **`https`** for the baked-in URL, the config-supplied URL, and after any redirect | The D39 escape hatch must not be able to downgrade transport. Free to enforce, impossible to add later | accepted |
| D54 | On skipping a tier, native **rewrites `active` to the build it actually returned** (or deletes it) | Otherwise a quarantined id left in `active` compares equal to `current.buildId` and the device never fetches again — a silent permanent stall | accepted |
| D55 | **P1 ships no application code**: `current.json`, bundles and blobs are static files served by Caddy; `hub` only writes them | The device-facing path should not depend on a process that does not exist yet. Rollback becomes rewriting one small file | accepted |
| D56 | **Native addresses markers under `context.getFilesDir()`**; Q17 resolved statically, not on a device | `FileSystemModule.smali:2784` builds `documentDirectory` as `Uri.fromFile(context.getFilesDir()).toString() + "/"`. The `ExponentExperienceData/` nesting that would have broken this applies to Expo Go, not a standalone build. JS sees a `file://` scheme and trailing slash; native sees a bare path — strip the scheme, do not double the separator | accepted |
| D57 | **The OTA hostname is DNS-only (grey cloud), never proxied** | A CDN in the body path can re-encode and break D49's sha256 invariant, which native can never recover from; it also intercepts the ACME HTTP-01 challenge so Caddy cannot issue a cert. | D62 | **Never republish an existing buildId with different bytes once the APK is installed** | The device compares identity, not content (D26): a reused id makes `current.buildId == active`, so it never fetches again and runs the old bundle forever, silently. | D63 | **Native emits one `adb logcat` breadcrumb (`Log.i("mjolnir-ota", …)`) in `getJSBundleFile`, naming the tier/id/path it selected, immediately before returning.** Corroborated off-device by a redeployable JS debug companion (reads the `mjolnir-ota/` marker dir) and a visible build-tag in the companion | The release build refuses `run-as`, and a plain-stock OTA bundle renders identically to the plain-stock embedded asset, so the first tier-selection tests (9.1/9.2) are otherwise unfalsifiable. `logcat` is not gated by the debuggable flag, so the line is readable on a release build with no root; a log is not "user-visible behaviour" (§8 forbids UI/prompts, not logs) and cannot affect selection. | D64 | **The baked-in OTA URL and token are placeholders in the smali** (`__MJOLNIR_OTA_URL__`, `__MJOLNIR_OTA_TOKEN__`), substituted immediately before assembling the APK. The build **must fail** if either placeholder survives into the assembled smali or the built dex | The native patch can be written, reviewed and diffed without a secret in it, and the secret never enters git. The failure mode it guards is silent and frozen: an unsubstituted placeholder ships an APK whose every OTA fetch 401s forever, indistinguishable on-device from a server outage. A `strings classes*.dex` grep is free; discovering it after signing is not | accepted |
| D65 | **GC preserves `bad-<id>` forever**; it sweeps the reclaimed bundle plus its `boot-ok-<id>` and `attempt-<id>-*` markers only. `bad-<id>` is a permanent 0-byte tombstone | §2's GC clause said "along with that build's markers", directly contradicting §4 and D52's operator-signed-off "never auto-cleared". The tombstone is the only durable record of "never fetch this id again". Cost is one empty inode per ever-quarantined buildId; capping or expiring them reintroduces the loop. Contract §2 amended to match §4 — a clarification of already-accepted semantics, not a reversal. **Operator sign-off 2026-10-20** | accepted |
